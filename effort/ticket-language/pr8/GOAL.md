## PR 8a — decisions (orchestrator, 2026-09-22)

1. **Types, in the package's spelling.** `model/ticket.qnt`: `type ReleasedContent = int` and `type ReleasedTicket = { id, content: ReleasedContent, dependencies: Set[int], workConfiguration: TaskDefinition, evaluationPlan: EvaluationPlan, finalizationConfiguration: int }` (package `ticket.qnt:5,56-63`); `Ticket.definition: ReleasedTicket` replaces `deps` and `program` (`ticket.definition.dependencies`, `ticket.definition.evaluationPlan.stages`; the instance's `begin` takes the plan itself). `Ticket.revision` does not arrive (8c). `releasedTicketValid` is the package's (`:265-271`) plus chuggy's bounds (`MAX_STAGES`, `N_TASKS`, positional stage keys — 7a decision 2 stands). `model/ticket-domain/evaluation/evaluation.qnt` becomes VERBATIM (`diff` empty); `model/AGENTS.md` says so and drops the six-line list. `EvaluatorDefinition.task` is a `TaskDefinition` per evaluator; that a stage's evaluators carry the same one is the release's rule (decision 6), not the model's.
2. **The source is a field of the ticket.** `Ticket.source: int`, `0` until dispatched. `Dispatch({ ticket, source })` sets it (package `DispatchTicket`, `:109`); a passed work report's `acceptedSourceRef` replaces it and is what the instance's `EvaluationInput.acceptedSourceRef` is begun with; an evaluation-failure rework, a finalization needs-work rework, a resume and the finalizer all run at the ticket's current `source` — **no spawn observes a source but the dispatch**. The package hangs the same value off `Work(WorkExecution).source`, `Escalated(WorkEscalation).source`, `FinalizationOperation.source` and `EvaluationInput.acceptedSourceRef`; chuggy carries one field on the record until PR 9 brings `TicketState`, and `ticket.qnt` says so at the field in two sentences. Invariant: `source > 0` exactly when the ticket has been dispatched; the copy's `acceptedSourceRef > 0` returns with it.
3. **The report carries the obligation.** `WorkResultReport { result: ValidatedTaskResult, acceptedSourceRef }` and `EvaluationResultReport { result: ValidatedTaskResult, verdict }` (package `:86-87`, minus the `ticket` the event carries — 7b's spelling); `TerminalFailureReport { evidence, kind }` untouched. `applyProduced` takes the `ValidatedTaskResult` (the copy's own). `reportMatchesTask` becomes the package's exact-obligation rule (README: "accepts a produced report only when its full task obligation equals the current obligation"): a work report's `result.obligation` equals `workTaskObligation(...)` and an evaluator's equals the one `currentTaskObligations` owes; a failure report still matches by identity. It is the same `NotEnabled` at the door until 8c names it. `contextRef` is the work cycle for a work task (package `:387-388`) and what the copy builds for an evaluator.
4. **Every ref is minted by the release, none is authored, and each is a fold of a digest the tree stores.** The wire does not change: the release body, `ReleaseDraft`, `authoringSchema` and the drafts read are as they are. `content` = the fold of the released revision's brief digest; `finalizationConfiguration` = the fold of the digest of the finalization binding resolved at release (`draft_brief.finalization_mode/_target` and the repository's landing as it stands at release — a landing default changed afterwards does not move a released ticket); `workConfiguration` = `{ workload, inputs, executionRequirements, resultContract }` resolved for kind `Work` under the release's configuration revision, and each evaluator's `task` the same four resolved for `Evaluation:<stage key>`: `executionRequirements` folds the materialized requirement's digest (`execution.requirement_digest` today), `workload` the configuration's image, `inputs` the block the briefing composes from, `resultContract` the manifest contract the worker attests. B names the exact material behind each of the four and says where a named one has no digest today (then the release computes and stores one). Folds are `result_digest_fold`'s shape in SQL and its TypeScript twin; a repository-less ticket (`BriefNamesNoRepository` is not raised; the sanity tickets are such) carries a reserved source reference distinct from every fold, named once in `src/adapters/postgres/schema/shared.ts`.
5. **The materialization is stored at release, and dispatch reads it.** 013 adds `ticket_definition (tenant, project, ticket, definition jsonb, digest text)` — one row per released ticket, written in the release transaction, holding the material the refs name (image, the requirement per kind and stage, the blocks, the finalization binding) in a shape `src/contract`/`src/interpreter` types — and `ticket_source (tenant, project, ticket, source bigint, repository text, commit text, ref text)` keyed `(tenant, project, ticket, source)`, one row per source the ticket has had (the dispatch's observation; each accepted work result's commit). `execution.requirement_*` is copied from `ticket_definition` at dispatch instead of re-materialized (`decision.ts:321-334`, `materializeExecutionRequirement` keeps one caller: the release). The refs themselves are read back from the journal's `CreateTicket` row (`journal_entry_release_ticket`), never from a second copy. `ticket_projection` unchanged.
6. **The release resolves.** `readiness.ts:192`'s `resolvedEvent` for `ReleaseDraft` carries the whole `ReleasedTicket`; the interpreter's `releaseTicketEvent(ticket, authoring, materials)` is pure and the adapter supplies the materials (configuration revision, brief, repository landing). Every evaluator of a stage gets the `Evaluation:<stage>` definition (7a decision 5). `draft_revision.authoring` stops being an encoded `CreateTicket` event (`encodeDraftAuthoring`, `authoring.ts:215`): it is the `ReleaseAuthoring` through `src/contract/authoring.ts`'s `authoringSchema`, and `parseDraftAuthoring` reads that — a definition depends on the revision chosen at release, so the draft cannot hold one; the wipe empties the table so no lift is owed (memory `stored-text-outside-the-journal`).
7. **The dispatch observes before it decides.** For the `Dispatch` command alone the writer observes the source at the ticket the command names, fills `source`, and refuses on `ExecutionSourceUnreadable`/`ExecutionSourceDenied` with no journal row — the same codes as today, decided before `execDecisionEvent`. `projectWriterExecutionSource`'s speculative re-decide (`projectWriter.ts:503-536`) is deleted; the `EscalateEvaluationFailure` park task E built for an unreadable rework source (`pr7/tasks/7b/E-report.md` §1b) goes with it, because a rework observes nothing. The pod's `TargetCommit` reference comes from `ticket_source` at the ticket's current `source`.
8. **The door builds the obligation from rows, never from the caller.** `submit_task_completion` (rewritten whole, 010/012's precedent; signature unchanged, `CREATE OR REPLACE`) journals the report of decision 3 with `result.obligation.task` from `execution_request_task`, `.definition` from the journal's `CreateTicket` row (work or the evaluator's stage), `.contextRef` per decision 3, `resultRef` as today's `result`, and `acceptedSourceRef` from `execution_result_source` for a passed work manifest — writing the `ticket_source` row under the same lock. A passed work manifest with no source row on a ticket that has a repository is refused (`BindingMismatch`'s shape; name it).
9. **013** = the guard as 008–012 with the wipe; `decision_event_is_valid` rebuilt whole: `CreateTicket` admits a `ReleasedTicket` (positive `id`, `content`, `finalizationConfiguration`; `dependencies` an array of positives; `workConfiguration` and every evaluator's `task` four positive ints; stages positional, evaluators unique within the bound — 011/012's rules kept) and drops 012's three dead conditions (`workFanout`, `finalizer`, `combinator`; survey 13); `Dispatch` admits `{ ticket, source }`; `TaskDone`'s two produced arms per decision 3. DDL: the two tables of decision 5, and `operation_completion_authority_is_its_boundary` re-rendered without `'ExecutionBlocked'` (survey 13). Render-diff 001–012 empty.
10. **Goldens** carry: a release whose definition is read back; a dispatch source carried into work; an accepted source replacing it and begun into the instance; a rework and a finalization at the accepted source; a report whose obligation differs refused. Twelve re-emitted.
11. **Out**: `Ticket.revision` and `UpdateTicket` (8c); `WorkInput`/`TicketState` (PR 9); events, obligations, refusal names; the worker, the fabric, the console, the configuration document.
