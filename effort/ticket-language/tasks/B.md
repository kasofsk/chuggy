## The rework cap, as implementation

The cap is the ticket service's policy, not the domain's. Add
`rework: { cyclesMax }` (non-negative integer) to the ticket-service
configuration in `src/roots/ticketService.ts` beside `domain`, threaded to
where the writer decides an `EvalReduce`. The disposition is a pure
function `reworkDisposition(ticket, cyclesMax)` in the interpreter:
Escalate when the ticket has already started more than `cyclesMax`
work cycles beyond its first (so `cyclesMax: 2` allows two reworks, the
old `BudgetedRework(2)` meaning), otherwise Rework. Count cycles from the
ticket's record and live set: a work cycle is a maximal run of Work-kind
tasks in id order; put that count as a pure helper in `src/domain/task.ts`
(`workCyclesStarted`) with its own unit test, and the disposition's test
beside the interpreter. The pick must be made where the writer has the
core and journaled on the event — `continuationSource` in
`src/adapters/postgres/readiness.ts` builds the command from a row and
cannot know the count; find where the writer turns a continuation into
the event it executes (`src/interpreter/projectWriter.ts`,
`projectDecision.ts`, `ticketCommand.ts`) and place it there. Read
`fix-the-assumption-not-the-hack` before choosing: the assumption that a
continuation row fully determines its event is the one that changed.

## One thing Task A left you (must do)

A pre-3 journal is unloadable until the store's decode lifts it. Rows
written before this change carry `{"type":"EvalReduce","value":<ticket>}`,
a bare int, which the generated wire union now refuses; the rig has
twelve such rows. Task A exported `dispositionInRecord` from
`src/actor/decisionSemantics.ts` and put a six-line lift in
`test/actor/decisionSemantics.test.ts` to keep fixtures replaying. Move
that lift to where the store decodes a stored row (`parseJournal` or the
load in `src/adapters/postgres/journal.ts` / `src/interpreter/wire.ts`,
wherever the row is decoded; the boundary rule keeps it out of the actor):
when `event.type === "EvalReduce"` and `event.value` is a number, rewrite
to `{ ticket: <n>, onFailure: dispositionInRecord(rec) }` before decoding,
and only for rows at semantics < 3 (a semantics-3 row with a bare int is
corrupt and is refused). Test it with a stored semantics-2 row whose rec
escalated and one whose rec reworked, and a semantics-3 bare-int row
refused. Then delete the lift from the actor test.
