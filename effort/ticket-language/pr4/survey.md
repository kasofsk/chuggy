## 4. The holds today — and the judgment

Mechanism. `finalizationNext` (`src/interpreter/finalizer.ts:822-847`) is pure and returns one of `Prepare | AwaitApproval | Promote | Reconcile | Abort | Conclude | Hold | Settled` (`:632-648`). A `Hold` reaches `finalizerHold` (`src/interpreter/finalizerRun.ts:331-340`), which **increments a tally and emits one metric. It writes nothing.** The claim is released, the `finalization_request` row stays `Open`/`Registered`, and the next pass re-claims and re-decides from the same rows. The ticket stays in `Finalization`; the console renders it identically to a healthy finalization (`ui/chuggy-ui/app/browser/ticket/TicketSituation.tsx:83-96`, heading `phaseLabel("Finalization") = "Finalizing"`, tone `info`).

**There is no operator exit.** `revocableIn` excludes `Finalization` (`model/domain.qnt:229-232`), the ticket is not `Escalated` so `retryableIn` (`:239-242`) refuses it and no `native_action` is open. The only thing that ends a hold today is the environment changing under it — or the project moving to `Deleting`/`Retention`, which turns the hold into `Abort` (`src/interpreter/finalizer.ts:712-714`, `:791-795`; `allClosingLifecycles` `:548-551`). This is the strongest argument for the step.

## 10. Surprises

1. **`ResumeFinalization` is a dead arm today.** Nothing stamps it: `escalate` is called only with `ResumeWork`, `ResumeRework`, `ResumeEvaluation` (`model/domain.qnt:466-475`, `:530-538`). Its only model test builds the state by hand with a mismatched reason (`model/tests/chuggy_test.qnt:499-503`). PR 4 makes a branch of `decideResumeTicket` reachable for the first time — the plan row reads it as "already there", which is true of the code and not of the reachability.
2. **A new label forces a new golden.** `declaredLabels` scrapes `model/domain.qnt` and `coverage.test.ts:64-75` fails on any declared label no golden fires. PR 4 must emit a 10th aimed trace. Not in the plan row's "007: outcome literal, finalization_request generation".
3. **Nothing decides *when* a hold becomes Unavailable.** Today a hold is re-decided every pass and self-heals the moment the environment is fixed, with no human involved. Escalating on the first hold converts every transient forge blip into a desk item; escalating after a dwell needs a durable "held since"/"held as" that **does not exist** — `finalizerHold` writes nothing (`finalizerRun.ts:331-340`). This is the goal's real open decision, and it is a 007 column either way if the desk is to say more than "unavailable".
4. **The submission gate has no evidence shape for Unavailable.** `006-rename.ts:287-310` fences every submission on `finalization_attempt`; the commonest holds have no attempt, and `:290-293` refuses a null attempt outside a `landing='None'` brief. A third arm that fences on nothing is a door the finalizer role can push any ticket out of Finalization through. `in_failure_kind` is the only evidence slot and its CHECK admits two values.
5. **A ticket in Finalization cannot be revoked** (`model/domain.qnt:229-232`) and is not retryable, so a held finalization is today unreachable by any operator action. Worth stating in the PR body: this is the failure the step prevents.
6. **`ApprovalDeclined` is terminal and is not "unavailable".** A resolved-Decline `native_action` is never withdrawn (`006-rename.ts:365-372` only withdraws a *standing open* one), so the hold is permanent, and the package's Unavailable resume — same operation, generation+1 — re-asks a question already answered.
7. **There are 31 hold reasons, not 18.** `FinalizerHoldReason` (`finalizerTelemetry.ts:47-63`) adds 13 operational ones including `PassCeilingReached`, which is a *budget of this pass* and must never become an escalation.
8. **Three holds are exhausted budgets** and one is a durable-row contradiction (`ContradictoryEvidence`) — PR 1 deleted every budget from the model on the grounds that a wall reached by counting is an implementation concern. Folding them into Unavailable re-imports that shape through the finalizer's door.
9. **The mc search grows.** `finalizationOutcomes.oneOf()` at `model/refinement.qnt:592` and `:626` gains a branch; `check-model.sh` is already the slowest gate and never in the hook.
10. **`ProposalRefused` is nine contradictions in one name** (`changeProposal.ts:274-283`), which split across `NeedsWork` and `Unavailable`. If the split matters, `finalization_change_proposal.creation_contradiction` already stores which one.
11. Size: 5 console arms + 2 console tests, 3 SQL IN lists + 2 CHECKs + one new binding arm, 4 domain/model switch sites, one golden, one roster test. **That is the handoff-removal size the plan promised — provided §10.3 and §10.4 are answered by decision rather than by code.**
