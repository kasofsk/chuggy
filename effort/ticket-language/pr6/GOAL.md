Migration 010 with the wipe. Branch `model/task-identity`, after 6a lands.

**Moved out.** The four opaque refs (`TaskDefinition`) go to PR 8 with `ReleasedTicket` (survey 10, Split b). The literal import stays PR 9 (survey 5). `Verdict` → `EvaluatorPass`/`EvaluatorFail` stays PR 7 (survey 13).

**Release coupling: none.** Wire task kinds `Work`/`Evaluation` stay at the boundary (`executionTaskKinds`, `execution_request_task.kind`, `CHUG_WORKER_TASK.taskKind`, the fabric's `CHUG_SCHEDULER_EXECUTION_POLICY` object); the worker image and the fabric do not move. ## PR 6b — decisions (orchestrator, 2026-09-21, drafted while 6a's sweep ran)

Branch `model/task-identity` off main once 6a (#TBD) is in. Briefs in `tasks/6b/`, reports beside them, ledger `reviews/6b-ledger.md`. Migration 010 with the wipe.

1. **The copy is the first commit.** `model/task-contract/task.qnt` is the package file byte for byte (survey 5); `ticket.qnt` imports it. The copy is gated like any model file, so its `taskDefinitionValid` and friends typecheck with no chuggy caller until PR 8 — that is the cost of a verbatim copy and is stated in the copy's neighbouring doc, not edited into the file.
2. **`Task = {identity: TaskIdentity, state: TaskState}`.** `Task.id` and chuggy's `TaskKind` go; the package's constructors take their names (survey 4). `Ticket.spawned` stays: it is the artifact number (`ProducedArtifact(retired.spawned)`) and the continuation fence (`taskSetGeneration`), and the interpreter mints the wire integer from it (decision 5). `Ticket.workCyclesStarted` arrives (package `ticket.qnt:76`): `spawnWork` increments it and names the work task `WorkTask{ticket, cycle}`; an evaluation stage `s` (0-based in chuggy) spawns `EvaluationTask{ticket, workCycle, stage: s + 1, generation: 1, evaluator: 1..fan}` (survey 3, the honest placeholder until PR 7). `resolveTask`, `retireLive`, `evalStage`, `decideTaskDone`, `reducibleWorkIn`/`reducibleEvalIn` and the four invariants go by identity. `taskIdentityValid` holds of every live task: an invariant.
3. **The journal event is `TaskDone{ticket, task: TaskIdentity, verdict, result}`.** `tid` goes. Enablement stays what it is (a `TaskDone` is enabled iff its identity names a live outstanding task of its ticket): that is the identity half of the exact-obligation refusal, and it is what this tree can honestly refuse before PR 8 puts the definition on the ticket (survey 6, 10; Split c). `contextRef` is the cycle and is inside the identity already. The refusal as a *decision result* (`TaskNotCurrent`) is PR 8's; do not add it.
4. **010 = the identity in columns, not JSON** (survey §3): `execution_request_task` gains `cycle`, `stage`, `generation`, `evaluator` (nullable per kind, one whole-identity CHECK per arm, `GRANT SELECT(col)` each), keeps `task` (the wire integer) and `kind`/`stage`-as-index goes or is restated as the package's positive key (S decides and says which; the console's three `+1` sites follow C). `decision_event_is_valid`'s `TaskDone` arm admits the structured `task` object and refuses `tid`. `submit_task_completion` is rewritten whole (008's precedent) to journal the identity read off `execution_request_task` in the same locked transaction; its signature need not change, so the grant may not either — S says. Guard as 008/009; the wipe.
5. **The wire integer stays** (survey 8, 12): `decisionPlan.ts requestTasks` mints `spawnedBefore + 1` for work and `spawnedBefore + evaluator` for a stage, injective and monotone per ticket, so `execution.task`, the unique, the FK, `ON CONFLICT`, the HTTP cursor and the page order are untouched. `CHUG_WORKER_TASK` gains nothing the worker reads (survey 7); `executionSummarySchema` gains `identity` beside `task` so the console stops inferring (decision 7).
6. **Requirement keys** (survey 9): `taskDefaults` keyed by the decimal id goes; `taskKindDefaults["Work"]` and `["Evaluation:<stage>"]` stay, `<stage>` becoming the package's positive key. The fixtures and the contract document follow.
7. **The console** draws cycle, stage, generation and evaluator off `identity` and deletes its inference: `cycleSetsOf`, the program-run reconstruction, the `/-\d+$/` grouping, and `runTotals`' `${taskKind}/${stage}` key that merged a stage across cycles (survey 11). Sorting by the integer stays (survey 12).
8. **Out**: `TaskDefinition`/`ValidatedTaskResult`/`TaskTerminal` producers (PR 8), `Verdict` rename (PR 7), the worker and the fabric (release coupling: none).
