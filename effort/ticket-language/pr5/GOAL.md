## Decisions (orchestrator, 2026-09-21)

**The sum.** `type Escalation = NoEscalation | WorkFailureEscalated | WorkExecutionUnavailableEscalated | EvaluationFailureEscalated | EvaluationBlockedEscalated | FinalizationUnavailableEscalated`, nullary (survey 1). `Ticket.reason` and `Ticket.resumeAt` become one `Ticket.escalation`. `Phase` stays flat (survey §1). **`EvaluationBlockedEscalated` enters now**, nullary, stamped by `decideExecutionBlocked` where it stamps `ResumeEvaluation` today (survey 2): the package has the constructor, and with it `resumeOf` is total on the variant and no record-kind derivation is needed anywhere. That is one new step label, `ticket-escalated evaluation_blocked_escalated`, and one aimed golden (an evaluation set blocked by a wall).

**Resume derived.** `pure def resumeOf(escalation): Resume` — WorkFailureEscalated → ResumeWork; WorkExecutionUnavailableEscalated → ResumeWork; EvaluationFailureEscalated → ResumeRework; EvaluationBlockedEscalated → ResumeEvaluation; FinalizationUnavailableEscalated → ResumeFinalization; NoEscalation → NoResume. `decideResumeTicket` switches on it. `retryableIn` becomes `hasOpenHumanTask` (survey 9); a native action's resolutions are always `["Resume","Revoke"]`. `Resume` stays as vocabulary; the stored field, the `resume_at` column, `ticketResponseSchema.resumeAt` and `TicketProjection.resumeAt` go.

**The `ExecutionBlocked` event loses its `reason`.** The only value it can carry after PR 3 is the collapsed name; the variant is determined by the phase interrupted. The wall name is evidence and travels outside the model: `submit_task_completion` is rewritten in 008 to build `ExecutionBlocked{ticket}` and to keep writing `execution.blocked_reason` as today; `decision_event_is_valid` follows. That is what lets the vocabulary map die.

**Evidence lives on the projection.** `ticket_projection` gains `escalation text NOT NULL DEFAULT 'NoEscalation'` (CHECK over the six) replacing `reason`, drops `resume_at`, and gains `escalation_evidence text` (nullable; CHECK: null when `escalation = 'NoEscalation'`). The projection writer fills the evidence from what the interpreter already holds: for an execution block, the `blocked_reason` of the execution or the `GitEvidence` name of the continuation path (survey 7; the two rosters are disjoint and one column admits both); for a finalization unavailable, the submission's `kind` (survey 6). The two correlated subqueries in `nativeReads.ts` and the fields they fed go. `native_action.reason` becomes `escalation` with the same six plus the settled-row `DependencyRevoked` arm; `request_finalization_approval` writes `'NoEscalation'`.

**The wire folds.** `reason`, `resumeAt`, `executionBlockedBy`, `finalizationBlockedBy` become one optional `escalation: { kind, evidence?, resumeAt }` on the ticket read; `escalationReasons` → `escalationKinds` (five, no `NoEscalation`); `blockedReasons`, `finalizationUnavailableKinds`, `resumePoints` stay as the rosters the evidence and the resume are drawn from. Breaks the wire; the console is the only client.

**Console.** One switch off `escalation.kind` for label, sentence, badge and tone; `escalation.evidence` for the wall line; `escalation.resumeAt` for the offer. `resumePoint.ts` shrinks to that; `ResumeSituation` loses `lastSet` and `resumeAt`; `ResumeOffer`'s `NotRead` arm goes with its only producer. Copy per the UI copy standard (nouns, one short line); `EvaluationBlockedEscalated` gets a label of its own.

**The wipe** is a tracked script, `deploy/rig/wipe-tickets.sql` (header states what it is for and what it keeps), owned by S: one `TRUNCATE` over every ticket-bearing table the survey lists (§3), then `project.head = 0` and the four counters to 1; keeps projects, configurations, repositories, bindings, installations, policies, selector settings, worker pools, clusters, capacity, admitted workers, recovery epochs. A `check-postgres` case proves it: seed through the public functions, run it, every listed table empty, counters reset, kept tables untouched. Release order: dump → scale the seven chuggy deployments to 0 → run the wipe → merge the fabric PR → reconcile (008 applies to the empty journal) → rollouts → sanity checks → a fresh ticket driven at least to Work on the rig.

**Not in this PR.** Payloads on the variants (PR 6–8). `project_continuation.expected_phase` (survey 8). Effects, Verdict. Fabric, worker.
