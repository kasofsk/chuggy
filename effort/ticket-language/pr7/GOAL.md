## PR 7a — decisions (orchestrator, 2026-09-22)

1. **Types, in the package's spelling.** `model/ticket.qnt`: `type EvaluatorDefinition = { key: int }` and `type StageDefinition = { key: int, evaluators: List[EvaluatorDefinition] }`; `Ticket.program: List[StageDefinition]` stays a list (`EvaluationPlan` arrives with the instance). `fanout` leaves the tree: model, generated mirror, domain, wire, schema, console. 7b's copy of `evaluation.qnt` replaces these two types without renaming anything.
2. **Well-formedness is the package's `planValid` minus `taskDefinitionValid`, plus chuggy's bounds.** Non-empty, at most `MAX_STAGES` stages; every stage has a non-empty evaluator list with unique positive keys, each `<= N_TASKS` (`N_TASKS` becomes the evaluator-key bound, the finite vocabulary the walk draws from); **a stage's key is its position, `key == index + 1`**, stated in `programsWellFormed` and in 011's `CreateTicket` arm. Positional stage keys are chuggy's rule, not the package's (which asks only uniqueness): the identity's `stage` is the stage's key (`taskIdentityFor` in the package), and holding it positional keeps `evalStage`, `schedulerRows.ts`'s one column→index site and the briefing's block selection correct without a program in hand. It is lifted when 7b's `StageRun` stores `stageIndex`. Evaluator keys are *not* positional: `{1, 3}` is a well-formed stage, and the walk draws such stages.
3. **Identity.** `EvaluationTask{ticket, workCycle, stage: <stage key>, generation, evaluator: <evaluator key>}`. `evaluationTaskOf` takes the stage key and the evaluator key and applies no offset (the `+ 1` moves into the one caller that has an index, or the caller passes `program[s].key`). `spawnEvalStage(j, ticket, s)` reads `program[s]` itself and spawns one task per listed evaluator. `stageGeneration(ticket, s)` counts record runs at the stage's first listed evaluator key (every run spawns exactly one of it). `retireLive` retires the live set in ascending evaluator-key order, not by walking `range(1, size + 1)`. `tasksWellFormed` and the stage-width invariant (`domain.qnt:948`) hold the live set's evaluator keys equal to `evaluatorKeys(program[s])`. `idsAccounted` and `spawned` are untouched.
4. **The wire integer is minted by position.** `decisionPlan.ts requestTasks` mints `spawnedBefore + <1-based position of the task in its set ordered by evaluator key>`, injective and monotone per ticket and byte-identical to today's for dense keys, so `execution.task`, the unique, the FK, `ON CONFLICT`, the cursor and the page order are untouched. `taskOrdinal` goes or becomes position-in-set (it needs the set); `tasksInOrdinalOrder` orders by evaluator key. `schedulerRows.ts` stays the one column→index site (`stage - 1`, justified by decision 2). The `evaluator` column of `execution_request_task` now carries the key; no DDL.
5. **The configuration is untouched.** A stage's evaluators all run the configured block for that stage (`taskBriefing.ts:468-476`, `executionRequirement.ts` key `Evaluation:<stage>`), as N identical evaluators did. Distinct per-evaluator briefs are a product feature, not convergence, and would couple the release to a re-import (survey §Release coupling). Say so in one line where the block is selected.
6. **The wire.** `programStageSchema` becomes `{key, evaluators: [{key}]}` (strict); the defaults' program is one evaluator per configured block with positional keys; `choices.stages` (a page of widths) goes and `choices.evaluatorsMax` (the key bound) arrives beside `programStagesMax`. The dispatch candidate's `program` and its stored text encoding follow. `contractDocument.json` and its tests follow. The console mints keys `1..n` from its count picker.
7. **011** = the guard as 008–010 with the wipe; `decision_event_is_valid`'s `CreateTicket` `prog` arm admits `{key, evaluators}` with positional stage keys and unique positive evaluator keys, refuses `fanout` and an empty evaluator list; `combinator` is carried as 010 carries it. No DDL. Render-diff 001–010 empty.
8. **The console** draws a stage as its evaluator count where it drew `fanout` (`ticketLedger.ts:244`, `TicketProvenance.tsx:133`, `creationStageLabel`), and sends keys. Nothing new is drawn: a key is not shown until an evaluator has something of its own to show (7b).
9. **Out**: everything in 7b above; `Verdict`; the worker and the fabric.
